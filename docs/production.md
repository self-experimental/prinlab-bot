# Production бота

Приложение: `/opt/printlab-bot-backend`. Compose-проект `printlab-bot-backend`.
Бот и PostgreSQL используют собственные тома. Сеть бота — `printlab-bot-backend`,
сеть БД — `printlab-bot-backend-db` (internal). Порт БД наружу не опубликован.
Проверка состояния доступна только на сервере: `http://127.0.0.1:8082/actuator/health`.

## Слайсер

Существующий backend работает в контейнере `printlab-backend-1`,
вызывает Bambu Studio 02.08.02.61 CLI и принимает multipart
`POST /api/print-plans/analyze-stl`. Распакованный бинарник на хосте находится
в `/opt/printlab/bambu/current/AppRun`; контейнер backend содержит собственный бинарник.
Бот не запускает графический интерфейс и не подключается к принтеру.

Только `slicer-proxy` соединяет сеть бота с существующей `printlab_default`.
Прокси разрешает один путь для POST, не публикует порт на хосте и не даёт
доступ к остальным API. Бот и его БД не подключены к сети сайта напрямую.
Существующий backend и его deployment не изменяются.

`SLICER_TRANSPORT=HTTP`, `SLICER_ENABLED=true`. Для PLA используется
`prusament-pla` из каталога backend, для PETG — настраиваемый профиль
`SLICER_BACKEND_PETG` (PETG по умолчанию выключен в продаже).
Бот выбирает результат с точно запрошенными слоем/заполнением и двумя периметрами;
если он отсутствует, оператор получает заявку для проверки. Ориентация сохраняется из STL.
Лимит backend — 15 МиБ, 100 000 треугольников. Более крупный допустимый для бота STL
попадает на ручную проверку. Тираж считается по отдельной пластине на изделие.
Занятость 429 и временные ошибки связи повторяются через 30 секунд, максимум 3 попытки.

## Фото и операторы

Клиент принимает условия в `/start`, затем отправляет фото или JPG/PNG документом.
Можно начать через `/model`. Фото, подписи и последующие текстовые описания
сохраняются в заявке со статусом `MODELING`; слайсинг ещё не запускается.
Оператор согласует моделирование вручную, отвечает `/model_reply НОМЕР текст`
и отправляет готовый STL с подписью `/model_stl НОМЕР`.
Клиент получает файл и кнопку выбора параметров печати.
Стоимость моделирования согласуется отдельно; автоматического тарифа на неё нет.

Настроены username `oilbanana,muslimitsuhide`. Каждый оператор должен написать
боту `/start` в личном чате: бот сохранит числовой ID из подлинного Telegram update.
После первой привязки одинаковый username не может автоматически получить другой ID.
Для смены владельца нужна ручная правка `operator_accounts` с проверкой личности.
Можно использовать `TELEGRAM_ADMIN_IDS` вместо привязки username.

Добавьте обоих операторов и `@printlab3dbot` в группу. Один оператор отправляет
`/operator_chat@printlab3dbot` в группе. Фото, заказы и служебные уведомления
после этого направляются в группу; без группы используются личные чаты операторов.
Команды изменения заказа выполняются в личном чате с ботом.
При превращении группы в supergroup новый ID сохраняется автоматически.
Себестоимость и служебные данные будут видны всем участникам подключённой группы.

## Конфигурация и секреты

`config/bot.env`: Telegram token, операторы, контакты, тарифы и параметры бизнеса.
`config/compose.env`: пароль БД, immutable `BOT_IMAGE`, сеть слайсера.
Оба файла принадлежат root, права `600`; каталог конфигурации `700`.
Локально токен находится в `.env` (`600`), deploy-ключ — в `.local/deploy_key`.
Они исключены из Git, Docker build context и deployment-архива.

Наценка и нижний порог — **50%**, версия тарифа `a1-mini-v4`.
Сбор 150 ₽ начисляется один раз на заказ. Акция в production выключена.
Предыдущие снимки предложений сохраняют свои ставки.

## GitHub Actions

Пайплайн `.github/workflows/ci-deploy.yml` запускает Maven verify, сценарии
на PostgreSQL 17 и тесты deployment. На main собирает linux/amd64 image
`ghcr.io/self-experimental/prinlab-bot` с меткой commit SHA и публикует его.
Deploy получает digest, подключается по закреплённому SSH host key и передаёт
короткоживущий registry token через stdin.

Секрет `DEPLOY_SSH_KEY` содержит отдельный ключ пользователя `printlab-bot-deploy`.
Его forced command допускает только `receive-deploy.py bot`; shell, forwarding
и выбор произвольного образа запрещены. Receiver проверяет digest, commit,
платформу и номер workflow. Код receiver и compose принадлежат root.

Перед обновлением сохраняется SQL backup. При неуспешном healthcheck,
Telegram getMe/getWebhookInfo или реальном слайсинге тестового STL
восстанавливается предыдущий image. Проверка не отправляет сообщения клиентам.
Backup не откатывается автоматически: миграции должны сохранять совместимость
с предыдущей версией приложения. Для первой установки предыдущего рабочего
image ещё нет; первичный запуск выполняется отдельно.

```bash
cd /opt/printlab-bot-backend
docker compose --env-file config/compose.env -f compose.yaml ps
docker compose --env-file config/compose.env -f compose.yaml logs --tail=100 bot
python3 smoke.py
```

Обновления compose, receiver и proxy устанавливаются отдельно администратором;
CI заменяет только образ приложения. Не запускайте второй polling-процесс
с production токеном. Для локального запуска `.env` оставляет `BOT_ENABLED=false`.
