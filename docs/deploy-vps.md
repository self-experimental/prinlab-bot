# Запуск на VPS: ручной слайсинг

Текущий режим: клиент присылает STL и параметры, оператор получает файл в Telegram, открывает его в Bambu Studio на своём компьютере и вводит общий расход пластика и время. Бот рассчитывает стоимость, отправляет предложение и ведёт заказ до выдачи. Слайсер на VPS не устанавливается и не запускается.

Нужен VPS с Linux, Docker Engine и плагином Docker Compose. Для Ubuntu 24.04 / 26.04 установка описана в [официальной инструкции Docker](https://docs.docker.com/engine/install/ubuntu/). Проверьте `docker version` и `docker compose version`; ниже предполагается, что текущий пользователь имеет доступ к Docker. Java и Maven на сервере не требуются: приложение собирается в Docker.

Публичный домен и входящие HTTP-порты боту не нужны: он обращается к Telegram по long polling. Серверу нужен исходящий HTTPS-доступ к Telegram, Docker Hub и Maven Central. База опубликована только на localhost:5434, приложение обращается к ней по внутреннему адресу `db:5432`.

На VPS с systemd включите автозапуск Docker: `sudo systemctl enable --now docker`. Так сервис будет доступен и после перезагрузки сервера; контейнеры имеют свою политику перезапуска.

## 1. Создать бота и узнать ID оператора

Откройте [официального BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и username. Сохраните выданный токен в своём менеджере паролей. В проект и чат разработки токен отправлять не нужно.

Для первоначального определения числового Telegram ID есть помощник без сторонних библиотек. Запустите на Mac или VPS с Python 3:

```bash
python3 scripts/telegram-id.py
```

Введите токен в скрытый запрос терминала. Откройте своего бота и отправьте `/start`; помощник покажет username и числовой ID отправителя. Если сообщение не успело прийти, повторите запуск. Запишите ID своего аккаунта в `TELEGRAM_ADMIN_IDS`. UUID пользователей будет создавать само приложение; в этой переменной нужен именно внешний числовой ID Telegram.

Помощник не отправляет сообщения и не записывает токен. Пока работает основной бот, его запускать не нужно: оба используют `getUpdates`. Если этот токен ранее использовался с webhook и вы переходите на PrintLab, остановите прежний сервис и выполните `python3 scripts/telegram-id.py --delete-webhook`. Эта опция снимает webhook, сохраняя ожидающие обновления.

## 2. Перенести исходники на VPS

На Mac в каталоге проекта:

```bash
bash scripts/package-deploy.sh
scp target/printlab-deploy.tar.gz USER@SERVER_IP:~/
ssh USER@SERVER_IP
```

Замените `USER` и `SERVER_IP` на SSH-пользователя и IP своего VPS. В архив включены исходники и настройки сборки; `.env`, модели, база, Git и локальный `target` в него не входят.

На VPS:

```bash
mkdir -p ~/printlab
tar -xzf ~/printlab-deploy.tar.gz -C ~/printlab
cd ~/printlab
cp -n .env.example .env
chmod 600 .env
nano .env
```

## 3. Заполнить `.env`

| Переменная | Что поставить |
| --- | --- |
| `DB_PASSWORD` | Свой случайный пароль новой базы вместо `replace-with-local-database-password` |
| `TELEGRAM_BOT_TOKEN` | Токен из BotFather |
| `TELEGRAM_ADMIN_IDS` | Числовой ID своего аккаунта; несколько ID через запятую |
| `BUSINESS_CONTACT` | Контакт для заказчика, например `@your_username` |
| `TERMS_URL` | HTTPS-ссылка на опубликованные условия заказа |
| `PRIVACY_URL` | HTTPS-ссылка на опубликованную политику обработки данных |
| `PAYMENT_INSTRUCTIONS` | Свои реквизиты и инструкция, по которой клиент оплачивает подтверждённый заказ |
| `PLA_BLACK_LABEL` | Фактический цвет PLA, например `'PLA белый'`; внутренний ключ пока остаётся прежним |
| `PAYMENT_RATE`, `TAX_RATE` | Свои действующие комиссия и ставка; сейчас примерные 0.03 / 0.04 |
| `PRICING_CONFIRMED` | `true` после проверки своих тарифов |
| `BOT_ENABLED` | `true` для подключения к Telegram |
| `SLICER_ENABLED` | `false` |
| `SLICER_PROFILE_CONFIRMED` | `false` |
| `PROMO_ENABLED` | Пока `false`, если не запускаете FIRST50 |

Не заменяйте ссылки на условия и политику фиктивными адресами: приложение показывает их клиенту перед согласием. Для первого запуска сохраните тариф PLA 1 000 ₽/кг, электричество 13 ₽/кВт·ч, брак 10%, пуск 150 ₽ на заказ, наценку 100% сверх пуска и время владельца 0 ₽/ч, если эти значения по-прежнему подходят. Ресурс принтера, обслуживание и упаковка остаются предварительными нормативами.

`DB_URL` в контейнере переопределяется автоматически, поэтому значение localhost в шаблоне менять для VPS не нужно. `compose.yml` дополнительно задаёт `SLICER_ENABLED=false` и `SLICER_PROFILE_CONFIRMED=false`, независимо от `.env`.

## 4. Запустить и проверить

```bash
docker compose --profile container config --quiet
docker compose --profile container up -d --build
docker compose --profile container ps
docker compose --profile container logs -f --tail=100 bot
```

Первая сборка скачивает JDK, Maven и зависимости. База получает миграции при старте приложения. Успешный запуск приложения в логах ещё не подтверждает правильность токена: затем обязательно откройте бота в Telegram и проверьте ответ на `/start`.

С операторского аккаунта отправьте `/start`, затем `/admin`. Проведите одну пробную заявку со вторым аккаунтом: согласие → STL → параметры → отправка. Клиенту должно прийти подтверждение заявки, оператору — STL и номер. Слайсинг-задание на сервере при этом не создаётся. Профили сервера и доступ к принтеру не требуются.

Политика `restart: unless-stopped` поднимает контейнеры после перезапуска Docker/VPS, если они не были остановлены вручную. Сессия SSH для работы бота не нужна; можно закрыть терминал. Должен работать только один экземпляр с этим токеном.

## 5. Обработать заказ

В Bambu Studio выберите A1 mini, PLA и параметры клиента. Проверьте, что модель и все поддержки помещаются на стол, а материал и цвет одни. Слайсьте весь тираж и сложите время и массу всех пластин. Масса уже включает поддержки; второй раз их не прибавляйте.

Если заказ №12 расходует 75 г и печатается 3 ч 30 мин, отправьте своему боту:

```text
/slice 12 75 210
```

Бот сам считает деньги по тарифам и отправляет клиенту цену. Эта короткая команда означает: дополнительные отходы и доставка 0, трудовые минуты 0, одна пластина. Если пластин две:

```text
/slice 12 75 210 2
```

Масса и время — суммарно для всего заказа, пуск всё равно 150 ₽ один раз. Если печать не проходит минимальную доходность, оператор получает сообщение о согласовании; клиент пока не получает предложение к оплате. Полный формат `/slice` с отходами и доставкой доступен в `/admin`.

Дальше клиент подтверждает предложение. Когда деньги действительно поступили, оператор вводит сумму из предложения и уникальный номер перевода. Для конкретного примера 75 г / 210 минут, текущих примерных комиссии/налога и выключенной акции цена составляет 610 ₽:

```text
/paid 12 610.00 bank-transfer-unique-id
/status 12 PRINTING
/status 12 QUALITY_CHECK
/status 12 READY
/status 12 COMPLETED
```

Статусы отправляйте по мере выполнения: начало печати, проверка качества, готовность, выдача. Клиент получает уведомления. Сумма в `/paid` должна совпасть с его предложением; 610 ₽ — только приведённый пример. Сам бот деньги не списывает. Для передачи фотографии или иных материалов клиенту пока используется ваш контакт; бот уведомляет о цене и статусах.

## 6. Обновление, остановка и копии

Для обновления распакуйте новую версию исходников в тот же каталог, сохраняя `.env`, затем:

```bash
docker compose --profile container up -d --build
```

База и загруженные файлы хранятся в именованных Docker volumes, переживают замену контейнеров. Не используйте `down -v` для рабочего проекта: эта опция удаляет данные. После изменения только `.env` тоже используйте `up -d`, чтобы контейнер был создан с новыми переменными; одного `restart` недостаточно.

Копия перед обновлением в контейнерном режиме:

```bash
mkdir -p backups
docker compose --profile container stop bot
docker compose exec -T db pg_dump -U printlab -d printlab -Fc > backups/printlab.dump
docker compose --profile container run --rm --no-deps -T --entrypoint tar bot -C /app/data -czf - . > backups/bot-data.tar.gz
docker compose --profile container up -d bot
```

Копируйте оба файла и `.env` в своё защищённое хранилище. Для простой остановки бота: `docker compose --profile container stop bot`. Проверка ошибок доставки — `/admin`, повтор уведомлений — `/retry_notifications`.

Источники: [создание бота](https://core.telegram.org/bots/tutorial), [getUpdates и webhook](https://core.telegram.org/bots/api#getupdates), [Docker Compose на сервере](https://docs.docker.com/compose/how-tos/production/), [сборка Docker в несколько этапов](https://docs.docker.com/build/building/multi-stage/).
