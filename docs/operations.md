# Эксплуатация

Для VPS с ручным слайсингом используйте [инструкцию развёртывания](deploy-vps.md). Ниже команды с `data/models` относятся к локальному Java-запуску; в Docker файлы находятся в томе `bot-data`, порядок копирования есть в инструкции VPS.

## Идентификаторы и доступ

`customers.id` — UUID. Все связи клиента с заказами, файлами и акцией используют UUID. `customers.telegram_id` — уникальный внешний номер Telegram; его тип определяется Telegram API. Числа в `TELEGRAM_ADMIN_IDS` проверяются только как внешний идентификатор источника сообщения. В аудите сохраняется UUID оператора, для системных действий — null.

Бот обрабатывает только личные чаты, в которых sender ID совпадает с private chat ID. Перед действием проверяются владелец заказа и права оператора. Себестоимость и доход не включаются в клиентское предложение. Административного HTTP API нет.

## Повторы и восстановление

Входящие обновления фиксируются вместе с бизнес-изменениями, offset и outbox. Повторный update не выполняется заново. Обработка идёт одним polling-экземпляром; не запускайте второй процесс с тем же токеном. Telegram может потерять обновления, если бот выключен дольше срока хранения на стороне платформы.

Исходящие сообщения имеют семантику «как минимум один раз»: если Telegram принял сообщение, а приложение упало до фиксации подтверждения, сообщение может повториться. Заказ, платёж и скидка при этом не дублируются. Ошибки недоступного чата видны в `/admin`, повтор — `/retry_notifications`.

Платёж имеет уникальную внешнюю ссылку/номер, а сумма обязана совпасть с актуальным предложением. После истечения предложения бот не принимает подтверждение оплаты по старой цене. Если клиент уже перевёл деньги вне срока, оператор сначала согласует дальнейшие действия с клиентом; MVP не списывает и не возвращает деньги сам.

## База и файлы

Миграции применяются Flyway при старте. Не редактируйте уже применённую миграцию; новые изменения оформляйте новой версией. `data/`, `.env`, `target/` исключены из Git.

Резервная копия PostgreSQL:

```bash
mkdir -p data/backups
docker compose exec -T db pg_dump -U printlab -d printlab -Fc > data/backups/printlab.dump
```

Копируйте отдельно `data/models`, используемые профили из `config/slicer/a1-mini`, `data/slicing` и защищённый `.env`. Для согласованной копии на этом MVP временно остановите приём новых заказов. Восстановление сначала проверяйте на отдельной базе, а не на рабочем экземпляре.

Файлы с одинаковым SHA-256 хранятся один раз, но метаданные владения разделены. После неуспешной транзакции может остаться неиспользуемый физический файл: автоматического удаления моделей в этой версии нет. Настройте срок хранения в своих опубликованных условиях и добавьте регулярную очистку после проверки ссылок из БД. Пользовательские имена файлов не используются как пути.

## Проверки запуска

Для включённого бота обязательны токен, оператор, подтверждённые тарифы, контакт, ссылки HTTPS на опубликованные условия и политика данных, инструкция оплаты. Деморежим запрещено совмещать с реальным ботом. Эти проверки не заменяют настройку продавцом своих условий, реквизитов и правил выдачи.

В папке проекта нет реальных токенов. Сборка и тесты не публикуют приложение и не включают продажи. Перед реальным запуском нужен личный пробный заказ через Telegram и проверенные тарифы. В текущем ручном режиме модель слайсит оператор на своём компьютере; профили на VPS не требуются.
