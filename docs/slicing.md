# Автоматический слайсинг

Production подключён к существующему backend через HTTP; параметры и ограничения описаны в [production.md](production.md). Ниже описан альтернативный CLI-режим с локальным бинарником и профилями.

После включения автоматического режима адаптер запускает Bambu Studio CLI; также поддерживается OrcaSlicer. Запуск выполняется через `ProcessBuilder`, без shell и подстановок пользовательских команд. Число копий передаётся движку; заполнение, слой 0,20/0,12 мм и поддержки записываются в отдельную полную копию профиля процесса. Это проверено по результату Bambu Studio, а не только по составу команды. Включены автоматическая ориентация и размещение. Масштаб не меняется: клиент загружает модель в миллиметрах.

## Что нужно от владельца

Выбран Bambu Lab A1 mini. Подготовлен профиль штатного сопла 0,4 мм и Generic PLA; владелец подтвердил PLA и штатное сопло. Цвет уточняется отдельно. Одного названия принтера недостаточно для точной себестоимости: на время влияют ускорения, максимальный объёмный расход материала, температуры и ограничения конкретного профиля.

Готовые полные профили Bambu Studio 02.08.02.61 находятся в `config/slicer/a1-mini`. Установите Bambu Studio и укажите постоянный путь к его CLI. Для своих откалиброванных настроек подготовьте отдельный каталог:

```text
machine.json   — ваш принтер и сопло
standard.json  — процесс для стандартного качества
fine.json      — процесс для детального качества
pla.json       — ваш PLA, включая плотность
petg.json      — PETG, если он доступен в боте
```

Предпочтительны полностью разрешённые настройки без зависимости от чужого пользовательского каталога. Если файл использует `inherits`, CLI должен иметь доступ к соответствующей базе профилей. Не подменяйте недостающий профиль «похожим» принтером: ошибка ускорений и расхода напрямую меняет цену.

Для встроенных профилей есть помощник `scripts/prepare-slicer-profiles.py`. Сначала найдите точные имена в установленной версии:

```bash
python3 scripts/prepare-slicer-profiles.py \
  --profiles-root /Applications/BambuStudio.app/Contents/Resources/profiles \
  --vendor BBL --list 'A1M'
```

Пример подготовки профиля Bambu Lab A1 mini 0,4 мм (используйте свои точные имена):

```bash
python3 scripts/prepare-slicer-profiles.py \
  --profiles-root /Applications/BambuStudio.app/Contents/Resources/profiles \
  --vendor BBL \
  --machine 'Bambu Lab A1 mini 0.4 nozzle' \
  --standard '0.20mm Standard @BBL A1M' \
  --fine '0.12mm Fine @BBL A1M' \
  --pla 'Generic PLA @BBL A1M' \
  --output ./data/profiles
```

Помощник разворачивает `inherits` и шаблоны `include`, проверяет указанную в профиле совместимость и не перезаписывает существующие файлы. Изменения собственных пользовательских настроек из интерфейса слайсера нужно экспортировать отдельно: встроенный профиль их не содержит.

В `.env` задайте абсолютный путь к исполняемому файлу. Пример macOS после самостоятельной установки:

```dotenv
SLICER_ENGINE=BAMBU_STUDIO
SLICER_EXECUTABLE=/Applications/BambuStudio.app/Contents/MacOS/BambuStudio
SLICER_VERSION=02.08.02.61
SLICER_PROFILES_DIR=./config/slicer/a1-mini
SLICER_ENABLED=true
SLICER_PROFILE_CONFIRMED=true
```

Имя executable проверьте в установленном приложении. Для Linux укажите путь к бинарнику или wrapper, который запускает AppImage без графического интерфейса.

## Очередь и результат

Заявка попадает в `slicing_jobs`. Worker забирает задание в короткой транзакции, затем запускает слайсер вне транзакции базы. По окончании считываются G-code всех пластин. Масса берётся из `total filament weight [g]` в Bambu Studio или `total filament used [g]` / `filament used [g]` в OrcaSlicer, время — из normal mode или Bambu total estimated time. Масса уже включает посчитанные слайсером поддержки. Собственные оценки объёма STL вместо настоящего слайсинга не используются.

Слайсер получает отдельный `--datadir` для каждого задания. Выполняется только экспорт G-code: создание 3MF с графическими миниатюрами для расчёта цены не требуется.

Число пластин сохраняется в оценке. По правилу владельца плата за запуск равна 150 ₽ на весь заказ, поэтому дополнительные пластины не добавляют ещё один сбор. По меткам G-code проверяется, что обработан весь тираж; частичный результат не превращается в предложение. Более одного использованного филамента отклоняется. Машинный профиль дополнительно проверяется на A1 mini, размеры 180×180×180 мм и нужное сопло.

Job сохраняет результат, SHA-256 модели и профилей, параметры заказа и указанную версию движка. Копии использованных профилей и G-code остаются в каталоге задания. Перезапуск освобождает истёкшую аренду задания; число попыток ограничено. Старый результат отменённого/пересчитанного заказа не изменяет актуальную цену.

При ошибке, отсутствии массы/времени или превышении 180 секунд клиент получает сообщение о проверке, оператор — причину и файл. У него остаются `/reslice` и резервная `/slice`. Пустой результат никогда не превращается в нулевую стоимость.

## Перед включением продаж

Сравните автоматический расчёт с интерфейсом той же версии Bambu Studio на нескольких своих моделях, двух высотах слоя и тираже больше одного. Затем сравните прогноз с контрольной печатью. `SLICER_PROFILE_CONFIRMED=true` означает, что именно эти профили проверены владельцем; наличие такого флага само по себе не доказывает точность.

Прогноз относится к машинному времени, не к сроку выдачи: очередь, охлаждение, контроль качества и выдача учитываются отдельно оператором. Автоматическое включение принтера и отправка G-code на устройство в MVP отсутствуют.

Для сервера ограничьте worker по CPU/памяти/диску и запускайте от отдельного пользователя. Приложение ограничивает размер STL, число треугольников и время процесса, но само не является ОС-песочницей. Профили устанавливает только владелец; клиент не может загрузить исполняемые сценарии постобработки.

Источник Bambu Studio: [CLI](https://github.com/bambulab/BambuStudio/wiki/Command-Line-Usage). Источники OrcaSlicer: [запуск](https://github.com/OrcaSlicer/OrcaSlicer/wiki/cli_mode), [действия](https://github.com/OrcaSlicer/OrcaSlicer/wiki/cli_actions), [загрузка настроек и клонирование](https://github.com/OrcaSlicer/OrcaSlicer/wiki/cli_misc). Формат G-code сверен с [исходным кодом OrcaSlicer](https://github.com/OrcaSlicer/OrcaSlicer/blob/main/src/libslic3r/GCode.cpp).

Загружаемая STL должна иметь габариты до 180×180×180 мм в исходной ориентации. Слишком большую модель бот просит заранее развернуть или разделить; автоматического масштабирования и разрезания нет. Окончательная проверка стола выполняется слайсером с учётом поддержек и каймы. Больший тираж размещается на нескольких пластинах.
