# PrintLab · Telegram-бот для 3D-печати

Production, группа операторов, фото и GitHub Actions: [инструкция](docs/production.md).

Клиент может прислать фото для ручного моделирования через `/model`. Оператор возвращает STL с подписью `/model_stl НОМЕР`; после этого доступен автоматический расчёт печати. Для общих уведомлений добавьте `@printlab3dbot` в группу с двумя операторами и отправьте `/operator_chat@printlab3dbot`.

Бот на Java 25 / Spring Boot 4.1.2 и PostgreSQL 17. Production использует **автоматический слайсинг через HTTP API существующего backend с Bambu Studio**. Клиент отправляет STL и параметры; бот получает массу и время и рассчитывает цену. Ручной расчёт оператора остаётся резервным вариантом. Бот рассчитывает цену, отправляет предложение и ведёт заказ до выдачи. Себестоимость и доход видит только оператор.

**Принтер — Bambu Lab A1 mini, область 180×180×180 мм, печать одним материалом и одним цветом. Отдельного сбора за запуск нет. Стоимость времени владельца равна нулю. Внутренние ID пользователей — UUID; `telegram_id` хранится отдельно.**

Запуск на VPS/Linux и GitHub Actions: **[production.md](docs/production.md)**. Локальный Compose остаётся средством разработки.

## Что реализовано

- Русский диалог с кнопками, сохранением черновика и источником `/start card01`.
- Проверка ASCII/binary STL, лимит 20 МиБ, проверка конечности координат, хранение по SHA-256.
- Очередь автоматического слайсинга, тайм-аут, восстановление незавершённых заданий после перезапуска, резервный ввод оператором.
- Расчёт пластика, отходов, электричества, амортизации, обслуживания, упаковки, брака, привлечения, комиссий, налога и доставки.
- FIRST50: 50% для двух участников. FIRST30: 30% ещё для восьми после двух оплат FIRST50. Один код на человека, скидка без денежного лимита, доставка без скидки. Место резервируется по кнопке «Применить промокод», уточняется при расчёте и погашается при оплате.
- Цель и минимальный порог дохода печати 50% к полным затратам, согласование отклонений с причиной, неизменяемые снимки расчётов.
- Подтверждение заказа клиентом, ручная регистрация реально полученной оплаты, производство, выдача, полный возврат.
- План/факт по расходу и времени, отчёт по поступлениям, возвратам, маржинальному доходу и источникам клиентов.
- Сохранение входящего offset и исходящих сообщений в одной транзакции. Отправка через outbox с повторными попытками.

Онлайн-эквайринг и управление самим принтером не подключены. Команда `/paid` регистрирует проверенное поступление, `/refund` — уже выполненный полный возврат. Физическая печать и выдача подтверждаются оператором.

## Посмотреть без токена и PostgreSQL

Требуется JDK 25. Maven загружается обёрткой проекта.

```bash
./mvnw -B -ntp verify
java -jar target/app.jar --spring.profiles.active=demo
```

Демонстрация проходит от заявки до выдачи в отдельной H2 в памяти, пишет `target/demo-result.json` и завершается. В ней используются **примерные** 75 г и 210 минут, отсутствуют реальный слайсинг, переводы денег и сообщения в Telegram.

Обычная цена покрывает расходы, комиссию и налог, а также целевой доход 50% к полным затратам. Сбор за запуск отключён. Доставка СДЭК вводится оператором отдельно и не уменьшает скидку на печать.

Для 75 г / 210 минут обычная цена печати составляет 310 ₽. FIRST50 уменьшает её до 155 ₽; такая скидка требует явного финансового согласования оператора. Проверяемые суммы и формулы: [docs/economics.md](docs/economics.md).

## Запуск реального бота

1. Создайте бота через BotFather. Запишите токен в локальный `.env`; не добавляйте его в Git и не отправляйте в чат разработки.
2. Скопируйте `.env.example` в `.env`. Укажите числовые Telegram ID операторов, контакт, опубликованные условия, политику обработки данных и инструкцию оплаты. Оператор должен сам открыть бота и отправить `/start`, чтобы получать уведомления.
3. Внесены настройки владельца: PLA 1 000 ₽/кг, электричество 13 ₽/кВт·ч, брак 10%, принтер 20 000 ₽. Ресурс 2 000 ч, обслуживание 5 ₽/ч и упаковка 35 ₽ пока приняты как предварительные нормативы. Сопло штатное 0,4 мм, материал PLA подтверждены владельцем; цвет выбирается из доступного каталога. `LABOR_PER_HOUR=0.00` оставляет ваше время бесплатным. Укажите собственные ставки налога и комиссии. `TARGET_PROFIT_MARKUP=0.50` задаёт заработок за печать 50% к полным затратам. `MINIMUM_PROFIT_MARKUP=0.50` — минимум 50% после скидок. Отклонение требует явного согласования. Установите `PRICING_CONFIRMED=true` только после проверки.
4. Для HTTP-слайсинга задайте `SLICER_TRANSPORT=HTTP`, `SLICER_ENABLED=true`, `SLICER_VERSION=remote-api` и адрес существующего backend в `SLICER_BACKEND_URL`. Ручной резерв: `/slice НОМЕР ГРАММЫ МИНУТЫ [ПЛАСТИН]`. Для локального ручного режима оставьте `SLICER_ENABLED=false`.
5. Промокоды управляются в админском меню «Промокоды». Миграция создаёт FIRST50 (2 участника), FIRST30 (8 участников после двух оплат FIRST50) и четыре TEST-кода со скидкой 10%, до конца 31.12.2026 по Москве. Даты, тип, процент и лимиты можно изменить в меню. Переменные PROMO_* остаются только для совместимости старой конфигурации и демонстрации; условия рабочих заказов берутся из БД.
6. Запустите PostgreSQL, соберите приложение и включите `BOT_ENABLED=true`.

```bash
cp .env.example .env
# Заполните .env в редакторе.
docker compose up -d db
./mvnw -B -ntp verify
./scripts/run-local.sh
```

`run-local.sh` загружает переменные из `.env`. Для ручного режима Bambu Studio работает отдельно на компьютере оператора. Бот использует long polling: публичный HTTP-адрес не нужен. Для этого токена не должно быть активного webhook и другого polling-процесса. Приложение рассчитано на **один экземпляр**.

Для VPS используйте `docker compose --profile container up -d --build`: Dockerfile собирает приложение из исходников и запускает его вместе с PostgreSQL, Java и Maven на сервере не нужны. Настройки слайсера читаются из `.env`. Production использует отдельный `deploy/compose.yaml`. Полная подготовка `.env`, перенос исходников и проверка — в [docs/deploy-vps.md](docs/deploy-vps.md).

HTTP-адаптер использует существующий API, а CLI-адаптер остаётся доступен с `SLICER_TRANSPORT=CLI` и проверенными профилями. Параметры: [docs/slicing.md](docs/slicing.md).

## Команды

| Клиент | Действие |
| --- | --- |
| `/new`, `/draft` | Создать или продолжить черновик |
| `/quantity 3` | Количество изделий |
| `/promo FIRST50`, `/promo -` | Указать или убрать промокод |
| `/orders`, `/order 12` | Последние заказы, детали заказа |
| `/cancel 12` | Отмена до оплаты |
| `/id` | Telegram ID |

| Оператор | Действие |
| --- | --- |
| `/admin` | Кнопки управления заказами и цветами в общем админском чате |
| `/reslice 12` | Повторить автоматический расчёт, когда автоматический режим включён |
| `/slice 12 75 210` | Ручной расчёт: 75 г и 210 минут на весь тираж, без доставки и дополнительных отходов |
| `/slice 12 75 210 2` | То же для двух пластин; сбора за запуск нет |
| `/slice 12 75 210 0 0 0 0 0 1` | Полный ручной ввод: граммы, минуты печати, подготовки и обработки, дополнительные отходы в граммах, себестоимость и цена доставки; последним аргументом число пластин (по умолчанию 1) |
| `/approve 12 рекламный бюджет` | Разрешить предложение ниже порога доходности с причиной |
| `/paid 12 500.00 bank-transaction-123` | Зарегистрировать полученную сумму; номер перевода уникален |
| `/status 12 PRINTING` | Начать печать оплаченного заказа |
| `/status 12 QUALITY_CHECK` | Контроль качества |
| `/status 12 READY`, `/status 12 SHIPPED`, `/status 12 COMPLETED` | Готовность к отправке, отправка и завершение |
| `/refund 12 refund-transaction-123` | Учесть выполненный полный возврат |
| `/actual 12 80 220 0 0 0 0 5` | Фактические граммы, минуты печати, подготовки и обработки, отходы, себестоимость доставки, прочие затраты |
| `/report` | Отчёт за всё время |
| `/retry_notifications` | Повторить неотправленные уведомления |

**В ручном вводе все величины относятся ко всему тиражу.** Масса включает поддержки и прочий материал, который уже посчитал слайсер. В поле отходов указывают только расход сверх этой массы. Фактический расход включает неудачные попытки; резерв брака к нему повторно не добавляется.

Основной интерфейс клиента и оператора работает кнопками. Клиент выбирает цвет, высоту слоя 0,08–0,28 мм, заполнение 1–100% и количество. Перед подтверждением заказа он указывает способ СДЭК, ФИО, телефон и адрес. Оператор вводит тариф доставки в группе; только после этого клиент получает итог для подтверждения. Реквизиты и трек-номер отправляются вручную через «Ответить клиенту» или reply на карточку. Согласованные тексты: [docs/bot-copy.md](docs/bot-copy.md).

## Экономика и структура

Формулы и ограничения отчётов: [docs/economics.md](docs/economics.md). Профили и поведение слайсера: [docs/slicing.md](docs/slicing.md). Эксплуатация и резервные копии: [docs/operations.md](docs/operations.md).

Пакеты разделены на `telegram`, `order`, `pricing`, `promotion`, `slicing`, `storage`. SQL находится в DAO. Каталог цветов расположен в `catalog`, диалоги изолированы по пользователю и чату. Денежные расчёты используют `BigDecimal`, валюту RUB и округление HALF_UP до копеек. Миграция `V0_1_0` соответствует версии приложения `0.1.0`.

## Проверка

```bash
./mvnw test                    # H2, без внешних сервисов
./scripts/test-postgres.sh     # отдельный временный PostgreSQL 17, удаляется после тестов
```

Проверяются расчёты по независимым контрольным суммам, структура файлов, извлечение параметров G-code, сценарий Telegram, UUID пользователей, права, повторные обновления и оплаты, возвраты, истечение цены, лимит акции при конкуренции и обработка результата слайсинга. Тестовый Telegram заменён заглушкой: тесты не отправляют сообщения людям.

Три дополнительных теста запускают настоящий Bambu Studio (либо OrcaSlicer), если заданы `SLICER_TEST_EXECUTABLE` и `SLICER_TEST_PROFILES` (каталог с `machine.json`, `standard.json`, `fine.json`, `pla.json`):

```bash
SLICER_TEST_EXECUTABLE=/Applications/BambuStudio.app/Contents/MacOS/BambuStudio \
SLICER_TEST_PROFILES=./config/slicer/a1-mini \
  ./mvnw -Dtest=SlicerCliTest test
```

Результаты выполненных проверок: [docs/verification.md](docs/verification.md).

Проверка на конкретном принтере требует его профилей, сопла и измерений контрольной печати. Время из слайсера — прогноз, а не гарантия фактической длительности.

Технические источники: [Telegram Bot API](https://core.telegram.org/bots/api), [Bambu Studio CLI](https://github.com/bambulab/BambuStudio/wiki/Command-Line-Usage), [Spring Boot](https://docs.spring.io/spring-boot/system-requirements.html).
